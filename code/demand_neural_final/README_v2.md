# 공개일 패턴 신경망 앙상블

제출 파일: `code/demand_neural_final/results_v2/최종제출_배치표_B지역_개선2.csv`

159개 대여소, D01~D30, 매일 총 **515대**입니다. 기존 제출은 529대입니다.
사이트에 실제로 업로드하지 않았습니다. 기존 원본 코드와 결과는 보존했습니다.

## 받은 자료 확인

새로 받은 D09·D10 CSV는 이전에 사용한 공개일 자료와 모든 값이 같습니다.
파일 해시는 인코딩/줄바꿈 등 저장 방식 때문에 다르지만 7,632행의 자료 내용은 같습니다.
스크린샷의 기존 제출 전체 점수는 **119,958.7**입니다.
기존 배치의 공개일 점수를 재계산하면 D09 **176,570**, D10 **154,854**로 화면과 정확히 일치합니다.
채점식이나 순유입 부호 오류는 발견되지 않았습니다. 순유입은 반납 − 대여입니다.

공개된 두 날짜만 최적화하면 N=532, 평균 벌점 165,710.5입니다.
기존 N=529의 같은 두 날짜 평균은 165,712로 이미 이 최적값에 가깝습니다.
이 두 날짜만의 최적값을 미공개 28일에 대한 최적값으로 해석하면 안 됩니다.

## 수정한 모델

기존 모델은 대여소 환경과 날짜·기상으로 초기 자전거 1대 추가의 벌점 변화를 예측하고 공개일 오차를 보정했습니다.
새 신경망은 공개일의 시간별 순유입, 변동성, 누적 순유입을 대여소별 입력으로 직접 받습니다.
공개일에서 계산한 초기 재고별 비용 증분을 기준으로 날짜·기상에 따른 차이를 학습합니다.
대여소·기상 인코더와 재고 수량별 디코더를 사용하고, 두 시드의 신경망을 평균냅니다.

새 신경망 단독과 추가 비용 보정은 A 검증에서 기존보다 나빠 최종안에 채택하지 않았습니다.
최종안은 **기존 두 모델의 평균 비용과 새 두 모델의 평균 비용을 1:1로 평균한 앙상블**입니다.
1:1 비율은 앙상블 평가 전에 고정했고 검증 점수에 맞춰 비율을 탐색하지 않았습니다.
공개 D09·D10에는 실제 비용을 사용합니다. 정수 DP로 모든 날짜의 N이 같고 거치대 상한을 지키는 배치를 구합니다.
공식 벌점 계수 `20*N + Σ(6*부족량² + 5*초과반납량 + 여유재고)`는 바꾸지 않았습니다.

## 비교 결과

같은 A 대여소 5분할을 사용했습니다. 다른 대여소의 D01~D23으로 학습하고,
평가 대여소에서는 D09·D10만 공개한 뒤 D24~D30을 평가합니다.
새 모델의 학습 목표에서는 공개 D09·D10을 제외하며 공개일은 입력으로만 사용합니다.
학습 횟수와 공개일 기준 비용/신경망 비용의 혼합 비율은 내부 대여소 3분할의 D17~D23에서 선택합니다.

| 방법 | A 검증 하루 평균 벌점 |
|---|---:|
| 이전 제출 모델 | 263,097.429 |
| 공개일 패턴 신경망 단독 | 263,945.571 |
| 추가 비용 보정 후보 | 264,009.000 |
| 최종 1:1 앙상블 | **262,941.571** |

최종안은 기존보다 약 **0.0592%** 낮습니다. 개선폭은 작습니다.
새 모델들을 비교하고 A 검증을 반복해 사용했으므로 이 수치는 독립적인 최종 성능 보장이 아닙니다.
전체 B 점수는 재제출 전에는 알 수 없습니다.
공개 두 날짜의 평균 벌점은 **165,712 → 165,718.5**로 6.5점 높아졌습니다.
이 공개일 결과는 모델 구성에 사용된 자료의 점수이며 별도의 테스트 성적이 아닙니다.

`relative_objective`는 N 선택에 영향을 주지 않는 상수 C(0)를 뺀 값입니다. 실제 대회 점수나 그 예측값이 아닙니다.
수치 검증과 날짜별 비교는 `code/demand_neural_final/results_v2/verification.json`에 저장합니다.

## 실행

Python 3.12 CPU 환경에서 실행했습니다. 저장소 루트에서 실행합니다. 기존 learn_data/와 input_data/ CSV 및 open_data/ 공개일을 읽습니다.

```powershell
python -m pip install -r code/demand_neural_final/requirements.txt
# 제공 모델로 최종 제출 파일 다시 생성
python code/demand_neural_final/run_neural_v2.py predict
# 전체 학습 및 비교 검증. 제공된 이전 모델/검증 자료가 있으면 그대로 재사용
python code/demand_neural_final/run_neural_v2.py train
python check_submission.py "code/demand_neural_final/results_v2/최종제출_배치표_B지역_개선2.csv"
python code/demand_neural_final/verify_signature_submission.py --previous-dir "code/demand_neural_final/results"
python code/demand_neural_final/test_signature_net.py -v
```

최종 파일 재생성에는 `run_neural_v2.py predict`를 사용하세요.
후보 모델 스크립트의 단독 predict는 후보 결과를 생성하므로 최종 앙상블 실행과 구분해야 합니다.
현재 공개 D09·D10에 맞춘 검증입니다. 공개일 구성이 달라지면 검증 분할을 점검하고 다시 학습해야 합니다.

모델은 `code/demand_neural_final/results/public_inventory.pt`와 `code/demand_neural_final/results_v2/signature_inventory.pt`입니다.
Git 버전은 기존 CSV 입력을 사용합니다. 원본과 학습·추론 수학은 같고 기본 입력/출력 경로만 다릅니다.
모델, 결과 CSV, 검증 JSON, NPZ는 루트 `.gitignore`로 제외하며 별도 ZIP에 제공합니다.


ZIP의 신경망_최종결과에 든 이전 모델과 자료는 results/에, 신경망_개선2_결과에 든 새 모델과 자료는 results_v2/에 복사하면 predict로 바로 재생성할 수 있습니다. 처음부터 실행할 때는 train을 사용합니다. 모델/결과는 Git에 포함하지 않습니다.
