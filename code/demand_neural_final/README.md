# 최종 B지역 배치 파일

사이트에 올릴 파일은 `code/demand_neural_final/results/최종제출_배치표_B지역.csv`입니다.
159개 대여소 × D01~D30, 정수 배치이며 매일 총 **529대**입니다.
대여소별 거치대 수 상한, 음수 금지, 매일 같은 총량을 모두 검사했고 공식 검사기를 통과했습니다.
보고서 PDF는 만들지 않았으며 사이트에 실제 제출하지는 않았습니다.

`B지역_시간별_순유입_예측.csv`는 보조 분석용 114,480행 예측입니다. 이 파일은 사이트 제출 양식이 아닙니다.
순유입은 항상 **반납 − 대여**이고, 양수이면 자전거 재고가 증가합니다.
최종 배치는 시간별 평균 예측을 그대로 누적하지 않고 아래의 배치 비용 신경망으로 구합니다.

## 신경망과 배치 방법

1. 수요 예측: 상대 거리 그래프와 대여소 환경, 달력·기상을 사용하는 잔차 MLP/시간 합성곱 후보를 비교했습니다.
   최종 예측 모델은 그래프 MLP 2개 앙상블입니다. 순유입 대칭 MSE에 누적 오차와 대여·반납 보조 Poisson 손실을 더했습니다.
   비대칭 손실로 평균을 음수로 밀어내지 않습니다. B 전체 평균 순유입 예측은 시간·대여소당 +0.004618대입니다.
2. 배치 비용 신경망: 초기 자전거를 x대에서 x+1대로 늘렸을 때 공식 벌점이 얼마나 변하는지 학습합니다.
   A 실제 시간별 경로를 공식 재고식에 넣어 학습 정답을 만들고, 대여소/이웃 환경과 하루 기상을 입력합니다.
   2개 신경망의 예측을 평균냅니다. 비용의 절댓값 대신 한 대 추가의 효과를 학습하므로, 초기 배치로 바꿀 수 없는 벌점은 목표에서 빠집니다.
3. 공개일 반영: Git에 팀원이 올린 B D09·D10 실제 자료만 사용합니다.
   대여소별 관측 비용 증분과 신경망 예측의 차이를 보정합니다. A 내부 검증으로 선택한 보정 비율은 평일 1.0, 휴일 0.5입니다.
   이미 공개된 두 날짜는 정확한 실제 비용을 사용합니다. 공개일도 30일 채점에 포함된다는 제출 안내를 따릅니다.
4. 정수 동적계획법: 1~총 거치대 수의 모든 N을 비교하고, 모든 날짜의 총량이 같은 조건에서 배치를 최적화합니다.
   사용 식은 하루 `20*N + Σ(6*부족량² + 5*초과반납량 + 여유재고)`입니다.
   이 최적성은 **신경망이 추정한 비용**에 대한 것이며, 미공개 B 실제 정답에 대한 최적성을 뜻하지 않습니다.

절대 x/y 좌표는 지역 간 원점·방향·축척 차이 때문에 직접 학습하지 않고 상대 거리 정보를 씁니다.
입력 엑셀에 한 달의 기상 자료가 있으므로 하루 전체 기상을 사용할 수 있습니다.

## 검증 결과와 한계

대여소를 5개 그룹으로 나누고 다른 대여소의 1~23일로 학습해, 제외된 대여소의 24~30일을 평가했습니다.
모델/학습 횟수/보정 비율은 1~23일 내부의 3개 대여소 분할에서 고릅니다. 최종 24~30일 점수로 설정을 고르지 않습니다.
공개일 활용 검증에서는 제외된 대여소의 D09·D10만 추가로 보여 주어 실제 B 입력 조건을 모사했습니다.

수요 예측 29,568개 대여소·시간의 MAE는 이전 대칭 GNN+LSTM **2.77533 → 2.75401**,
RMSE는 **5.34449 → 5.27449**입니다. 오차 감소가 배치 성능 향상을 자동으로 뜻하지는 않습니다.

| A 배치 검증 방법 | 대상 대여소에서 사용한 실제 일수 | 공식 하루 평균 벌점, 작을수록 좋음 |
|---|---:|---:|
| 이전 대칭 GNN+LSTM + 평균 경로 배치 | 0 | 271,058.714 |
| 새 신경망 후보 선택, 공개일 미사용 | 0 | 274,174.429 |
| 공개 2일 비용을 그대로 평균한 기준선 | 2 | 263,774.857 |
| 최종 신경망 + 공개 2일 보정 | 2 | **263,097.429** |

표의 모든 방법은 동일한 5개 평가 대여소 그룹별로 N을 최적화하고 결과를 합산했습니다.
최종 방법은 공개일 미사용 새 신경망보다 약 4.04%, 같은 2일을 사용한 단순 기준선보다 약 0.26% 낮았습니다.
공개일 미사용 모델과의 차이에는 **추가로 주어진 관측 정보의 효과**가 포함됩니다. 신경망 구조만의 개선 수치로 해석하면 안 됩니다.
여러 차례 모델을 개발하며 A 검증을 확인했으므로 이 수치는 독립적인 대회 비공개 성적이 아닙니다.
B의 미공개 28일 실제 수요와 전체 대회 점수는 알 수 없습니다. 공개 2일 점수는 학습에 이용한 자료의 점수입니다.

`relative_objective`는 상수 C(0)를 뺀 상대 목적함수라 음수일 수 있습니다. 예상 대회 벌점으로 읽으면 안 됩니다.
공식 `score.py`의 `GSMMC_FORMULA` 결과와 자체 계산이 일치하는 것도 확인했습니다.

## 실행

Python 3.12 CPU 환경에서 재현했습니다. 저장소 루트에서 실행합니다. 입력은 learn_data/와 input_data/의 기존 CSV를 읽습니다.

```powershell
python -m pip install -r code/demand_neural_final/requirements.txt
# 제공된 모델로 최종 제출 파일 다시 생성
python code/demand_neural_final/run_neural_submission.py predict
# 처음부터 학습, 내부 검증, 최종 제출 파일 생성
python code/demand_neural_final/run_neural_submission.py train
python check_submission.py "code/demand_neural_final/results/최종제출_배치표_B지역.csv"
python code/demand_neural_final/verify_neural_submission.py
python code/demand_neural_final/test_neural_models.py -v
```

최종 파일 생성은 반드시 `run_neural_submission.py`로 실행하세요. 개별 후보 스크립트의 `predict`는 후보 배치로 파일을 덮어쓸 수 있습니다.
현재 검증은 공개 D09·D10 기준입니다. 공개일 구성이 바뀌면 재학습이 필요하며, 17일 이후 공개일은 검증 기간과 겹치므로 먼저 검증 분할도 수정해야 합니다.
`train`은 검증을 포함하므로 CPU에서 수 분 이상 걸립니다. 같은 패키지 버전·CPU 설정에서 재현을 확인했습니다.

학습된 모델과 실행 결과는 ZIP으로 제공합니다. Git에는 코드·설명·테스트만 넣고 루트 `.gitignore`에서 결과 폴더 전체를 제외합니다.
기존 원본과 팀원 코드는 유지하며 Git용 `code/demand_neural_final/`에서는 입력을 저장소 CSV로 읽도록만 별도로 바꿉니다.

## 파일 구성

- `run_neural_submission.py`: 전체 학습/재생성 실행 진입점
- `bike_neural_final.py`: 평균 순유입 신경망과 시나리오 후보
- `bike_inventory_net.py`: 초기 재고별 비용 증분 신경망과 공개일 미사용 비교
- `bike_public_transfer.py`: 공개일 보정, 검증, 최종 배치
- `neural_allocation.py`: 공식 재고 비용과 정수 DP
- `bike_net_flow.py`: 이전 원본의 데이터 로더를 재사용하는 의존 파일. 원본을 보존했습니다.
- `code/demand_neural_final/results/*.pt`, `reference.npz`: 학습 모델 및 시나리오 참조
- `A_validation.json`, `inventory_validation.json`, `public_transfer_validation.json`: 검증 설정과 결과
- `verification.json`: 제출 조건과 공식 채점식 일치 검증
- `open_data/`: 팀원이 Git에 올린 공개 D09·D10 CSV 사본. 파일 해시는 B_summary.json에 기록됩니다.


## Git 결과 제외 및 모델 복원

처음 실행할 때는 `train`으로 모델을 학습합니다. 제공 ZIP의 신경망_최종결과 폴더 안 모델·NPZ 파일을 이 폴더의 results/에 복사하면 `predict`로 바로 재현할 수도 있습니다. 학습 결과(CSV, JSON, PT, NPZ)는 루트 .gitignore의 results/와 runs/ 규칙으로 제외됩니다. 기존 demand_net/demand_decision/demand_rule 및 데이터는 변경하지 않습니다.
