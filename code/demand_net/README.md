# 순유입 GNN+LSTM 대칭 손실 수정 결과

각 대여소·시간의 `반납 - 대여`를 예측하는 기존 GNN+LSTM 구조를 유지하고 기본 손실을 대칭 제곱오차로 수정했다. 양수는 재고 증가, 음수는 재고 감소이며 단위는 건/시간이다.

기존 `3 × max(예측−실제, 0)² + max(실제−예측, 0)²`는 예측을 낮추는 방향으로 학습됐다. 수정 기본값 `over_weight=1`은 `mean((예측−실제)²)`와 같으며 학습과 내부 epoch 선택에 모두 적용한다. 그래프, 정점 특성, GNN, LSTM, 표준화, 옵티마이저, seed, 외부 검증 분할은 그대로다. 예측 합계를 강제로 0으로 맞추거나 음수를 잘라내는 후처리는 하지 않는다.

기존 모델 파일을 잘못 재사용하지 않도록 저장된 over_weight와 현재 요청한 설정이 다르면 predict를 중단한다. 옵션만 바꾸는 것으로 이미 학습된 모델이 수정되지는 않는다. 새 모델을 사용하거나 다시 train해야 한다. 기존 3배 모델 재현은 train/predict 모두 `--over-weight 3`을 명시한다.

## A 검증

이전과 같은 seed=202606 대여소 5분할이다. 평가 대여소의 실적 전체를 제외하고 나머지 대여소의 6월 1~23일로 학습하여 평가 대여소의 24~30일을 예측한다. 모든 176개 대여소가 한 번씩 평가되어 29,568행이다. epoch는 별도 내부 대여소로 선택했다.

| 지표 | 기존 3배 손실 | 수정 대칭 손실 |
|---|---:|---:|
| 순유입 MAE | 3.044379 | 2.775332 |
| 순유입 RMSE | 5.587589 | 5.344490 |
| 평균 오차(예측−실제) | -1.370790 | +0.042759 |
| 평균 예측 순유입 | -1.386009 | +0.027540 |

실제 평균 순유입은 -0.015219다. 새 모델의 큰 음수 편향은 줄었지만 완전한 예측은 아니다. 항상 순유입 0을 예측하는 기준의 MAE는 2.716518로 새 모델보다 작고, RMSE는 5.776003으로 새 모델보다 크다. B의 실측 정답은 없어 B 정확도를 계산할 수 없다.

외부 분할에서 선택한 epoch는 14, 6, 11, 5, 1이며 최종 모델은 중앙값인 **6 epoch**로 전체 A를 재학습했다. 앞선 원인 진단에서 사용한 고정 7 epoch 실험과 구분한다. 그래서 최종 B 평균 예측은 진단 실험의 +0.0480과 다르다.

## 실제 배치 벌점 확인

기존 모델의 5분할 예측을 당시 선택된 epoch로 다시 생성했고, 기존 검증 지표와 일치함을 확인했다. 기존·수정 모델 각각의 미사용 대여소 예측으로 같은 정수 DP를 실행하여 7일에 공통인 N과 일별 배치를 선택한 뒤 A 실측 수요로 평가했다. 평가 정답은 배치 선택에 사용하지 않았다.

| 배치 입력 | 실제 일평균 대회 벌점 | 선택된 A 총량 N |
|---|---:|---:|
| 기존 3배 손실 예측 | 276,882.714 | 1,064 |
| 수정 대칭 손실 예측 | 271,449.714 | 472 |
| 대여소당 매일 1대 | 279,890.714 | 176 |
| 매일 수용량 절반(내림) | 279,999.286 | 1,316 |

동일 DP 비교에서 실제 벌점이 약 **1.96% 감소**했다. 공식 `score.py`와 계산 결과도 대조했다. N=472는 A 검증 배치의 값이며 B 권장 총량으로 사용하면 안 된다. 결과는 `A_allocation_comparison.json`에 있다. 이 비교는 점 예측을 DP에 넣은 평가이며, 앞서 별도로 만든 CatBoost 시나리오 모델의 평가 절차와 구분한다.

## B 결과

159개 대여소 × 30일 × 24시간, 114,480개 예측을 생성했다. CSV 열은 `date,hour,station_id,pred_net_flow`이고 소수 넷째 자리까지 저장했다. 날짜·시간·대여소 키가 모두 존재하고 중복·결측·무한값이 없다.

| B 예측 분포 | 기존 3배 손실 | 수정 대칭 손실 |
|---|---:|---:|
| 평균 순유입 | -1.329481 | +0.163802 |
| 평균 절대 순유입 | 1.794052 | 1.460583 |
| 음수 예측 비율 | 82.8573% | 42.9149% |
| 30일 예측 합계 | -152,198.96 | +18,752.09 |

위 분포 통계는 저장 전 예측값 기준이다. CSV 반올림으로 아주 작은 차이가 있을 수 있다. 순유입 합계가 0이어야 하는 조건은 없으며 이 합계는 B 실측 부족량이나 정확도가 아니다.

배치 코드에서는 `z = 현재 재고 + pred_net_flow`로 사용한다. `대여−반납`으로 취급하여 빼면 부호가 뒤집힌다. 팀 저장소의 순유입 DP 코드는 이 부호를 올바르게 사용하지만 현재 입력 경로가 다른 모델 폴더이므로 아래 Git 안내를 참고한다.

## 파일과 실행

- `bike_net_flow.pt`: 수정된 대칭 손실 학습 모델.
- `B지역_시간별_순유입_예측.csv`: B 예측 결과.
- `A_검증예측.csv`: A 미사용 대여소의 실측·예측. 29,568행.
- `A_validation.json`: 전체 검증 지표, 분할, 최종 epoch, 손실 설정.
- `B_summary.json`: 모델 설정과 B 예측 분포.
- `A_allocation_comparison.json`: 동일 DP로 비교한 A 실제 벌점.

## 저장소 실행 방법

Python 3.12 CPU 환경에서 검증했다. 저장소 루트에서 실행하며 기존 `learn_data/`, `input_data/` CSV를 읽는다.

```sh
python -m pip install -r code/demand_net/requirements.txt
python code/demand_net/forecast_net.py train
python code/demand_net/forecast_net.py predict
python -m unittest discover -s code/demand_net -p 'test_*.py' -v
```

기본 출력은 `code/demand_net/results/`다. 새 `bike_net_flow.pt`를 이 폴더에 넣으면 predict로 재학습 없이 출력할 수 있다. 기존 3배 손실 모델을 넣고 기본 설정으로 predict하면 손실 설정 불일치로 중단한다. 새 기본값만 적용하고 기존 가중치를 계속 쓰는 실수를 방지한다.

train은 학습·검증·B 출력을 수행한다. `A_allocation_comparison.json`은 이번 별도 배치 검증에서 생성한 보고서이며 train의 기본 출력에는 포함되지 않는다.

비교 실험은 별도 폴더를 지정한다. over_weight>1은 과소예측을 유도하는 설정이므로 기본 평균 예측과 구분한다.

```sh
python code/demand_net/forecast_net.py train --over-weight 3 --output-dir code/demand_net/runs/asymmetric
python code/demand_net/forecast_net.py predict --over-weight 3 --output-dir code/demand_net/runs/asymmetric
```

`code/4_NetToOut.py`의 현재 PRED_PATH는 `code/demand_decision/results/`를 가리킨다. 이 GNN+LSTM 결과로 DP를 실행할 때는 해당 입력 경로를 `code/demand_net/results/B지역_시간별_순유입_예측.csv`로 지정해야 한다. 두 CSV의 열 형식과 순유입 부호는 같다. 이번 수정에서는 팀원의 DP 코드·입력 경로와 데이터 파일을 변경하지 않았다.

원본 Excel용 코드와 이 CSV용 사본은 입력 로더·경로만 다르다. A/B의 처리 후 모든 배열이 정확히 같고, 같은 학습 모델로 생성한 B 예측 CSV 및 B_summary.json의 SHA256도 같다. 회귀 검사는 대칭 손실·평균 선호·기존 비대칭 체크포인트의 오사용 차단을 확인한다.

저장소 루트 `.gitignore`의 `code/demand_net/results/`와 `code/demand_net/runs/`가 모든 실행 산출물을 제외한다. CSV, JSON, PT, NPZ 등은 로컬에서 생성하거나 별도 제공받으며 Git에는 코드·문서·검사만 올린다.
